# دامنه‌ی MVP (فقط بعد از تأیید مصاحبه‌ها)

## ویژگی‌ها
**مربی/موسسه**
- ساخت آزمون از چند سؤال (تصویر چارت + گزینه‌ها + تصویر پاسخ + توضیح)
- دعوت شاگرد با لینک یا کد
- گزارش: نمره‌ی هر شاگرد، سؤال‌های ضعیف کلاس، روند پیشرفت

**شاگرد**
- ورود با لینک موسسه، حل آزمون، دیدن نتیجه و پاسخ‌ها
- (بعداً) گواهی یا کارنامه‌ی قابل‌اشتراک

**خارج از MVP:** جایزه نقدی، پرداخت بین کاربران، مارکت‌پلیس عمومی، چت AI.

## تغییرات روی کد فعلی (`backend`)
مرحله ۱ - امنیت و صحت (الزامی)
- [ ] تصحیح سمت سرور: ورودی `isCurrect` را از `submitQuiz` حذف کن؛ سرور خودش گزینه را با `answer` مقایسه کند.
- [ ] جواب درست (`answer`) و تصویر پاسخ در API شاگرد برگردانده نشود، مگر بعد از ثبت پاسخ.
- [ ] بررسی مالکیت در `updateQuiz` / `deleteQuiz` (فقط سازنده یا مربی همان موسسه).
- [ ] `cors` را به دامنه‌های مجاز محدود کن؛ `sequelize.sync({alter:true})` را با migration عوض کن.
- [ ] محدودیت اندازه و نوع فایل آپلود.

مرحله ۲ - چندمستأجری
- [ ] مدل `Organization` (موسسه)
- [ ] مدل `Membership` (userId, orgId, role: owner/instructor/student)
- [ ] هر آزمون و سؤال به یک `orgId` وصل شود؛ همه‌ی کوئری‌ها با `orgId` فیلتر شوند.

مرحله ۳ - آزمون و گزارش
- [ ] `Pack` را به `Exam` تغییر نام بده؛ فیلدهای `price`, `isFree`, `public`, `category` حذف یا ساده شوند.
- [ ] مدل `ExamAttempt` (شاگرد، آزمون، نمره، زمان شروع/پایان) به‌علاوه‌ی `QuizAttempts` فعلی.
- [ ] endpoint گزارش: نمره‌ی هر شاگرد، میانگین کلاس، درصد پاسخ درست هر سؤال.
- [ ] حذف `calculatePackPrice` / `getPackPrice` / `getQuizPrice`.

## فرانت
- `quizer` → پنل مربی (ساخت آزمون و گزارش)
- `user` → پنل شاگرد (حل آزمون)
- `main` → صفحه‌ی فرود و ثبت‌نام موسسه

## سؤال‌های عینی (مهم)
سؤال «ذهنی» اعتبار را خراب می‌کند. ترجیح: سؤال‌هایی که نتیجه‌ی قیمتی دارند.
مثلاً «بعد از این الگو قیمت بالا رفت یا پایین؟» و پاسخ از داده‌ی واقعی چارت تعیین شود، نه نظر مربی.
